== Comparison to Other Array Libraries (mdspan, Boost.MultiArray, etc)

The C++23 standard provides `std::mdspan`, a non-owning _multidimensional_ array.
So here is an appropriate point to compare the two libraries.
Although the goals are similar, the two libraries differ in their generality and approach.

The Multi library concentrates on _well-defined value- and reference-semantics of arbitrary memory types with regularly arranged elements_ (distributions described by strides and offsets) and _extreme compatibility with STL algorithms_ (via iterators) and other fundamental libraries.
While `mdspan` concentrates on _arbitrary layouts_ for non-owning memory of a single type (CPU raw pointers).
Due to the priority of arbitrary layouts, the `mdspan` research team didn't find efficient ways to introduce iterators into the library. 
Therefore, its compatibility with the rest of the STL is lacking.
link:https://godbolt.org/z/aWW3vzfPj[Preliminarily], Multi array can be converted (viewed as) `mdspan`.

link:https://www.boost.org/doc/libs/1_82_0/libs/multi_array/doc/user.html[Boost.MultiArray] is the original multidimensional array library shipped with Boost.
This library can replace Boost.MultiArray in most contexts, it even fulfills the concepts of `boost::multi_array_concepts::ConstMultiArrayConcept` and `...::MutableMultiArrayConcept`.
Boost.MultiArray has technical and semantic limitations that are overcome in this library, regarding layouts and references;
it doesn't support value-semantics, iterator support is limited, and it has other technical problems.

link:https://eigen.tuxfamily.org/index.php?title=Main_Page[Eigen] is a popular matrix linear algebra framework library, and as such, it only handles the special 2D (and 1D) array case.
Instead, the Multi library is dimension-generic and doesn't make any algebraic assumptions for arrays or contained elements; it can still be used to _implement_, or be combined with, dense linear algebra algorithms.

Other frameworks include the OpenCV framework, which is too specialized to make a comparison here.

[#appendix_fortran]
== Multi for Fortran Programmers

This section summarizes simple cases translated from Fortran syntax to C++ using the library.
The library strives to give a familiar feeling to those who use multidimensional arrays in Fortran.
Arrays can be indexed using square brackets (`[]`) or parentheses (`()`), which would be more familiar to Fortran syntax.
The most significant differences are that array indices in Fortran start at `1`, and that index ranges are specified as closed intervals, while in Multi, they start by default at `0`, and ranges are half-open, following C++ conventions.
Like in Fortran, arrays are not initialized automatically for simple types (e.g., numeric); such initialization needs to be explicit.

|===
|                             | Fortran 90                                           | C++ Multi

| Declaration/Construction 1D | `real, dimension(3) :: numbers` (at top)           | `multi::array<float, 1> numbers(3);` (at scope)
| Initialization (3 elements) | `numbers = (/ 1.0, 2.0, 3.0 /)`                        | `numbers = { 1.0F, 2.0F, 3.0F };`
| Element assignment (3rd)    | `numbers(3) = 99.0`                                | `numbers[2] = 99.0F;`
| Element access (print 3rd)  | `print *, numbers(3)`                              | `std::cout << numbers[2] << '\n';`
| Printing all elements       | `print *, numbers`                                 | `std::cout << numbers;` (needs `multi/io.hpp`) or  `std::print("{}", numbers);` (needs pass:[C++23])
| Re-initialization           | `numbers = (/ 10.0, 20.0, 30.0 /)`                | `numbers = {10.0F, 20.0F, 30.0F};`
|===

In the more general case for the dimensionality, we have the following correspondence:

|===
|                              | Fortran 90                                           | C++ Multi

| Construction 2D (3 by 3)     | `real(kind=8) :: A2D(3,3)` (at top)               | `multi::array<double, 2> A2D({3, 3});` (at scope)
| Construction 2D (2 by 2)     | `real(kind=8) :: B2D(2,2)` (at top)               | `multi::array<double, 2> B2D({2, 2});` (at scope)
| Construction 1D (3 elements) | `real(kind=8) :: v1D(3)` (at top)                 | `multi::array<double, 1> v1D(3);` (at scope)
| Assign the 1st column of A2D | `v1D(:) = A2D(:,1)`                               | `v1D( _ ) = A2D( _ , 0 );`
| Assign the 1st row of A2D    | `v1D(:) = A2D(1,:)`                               | `v1D( _ ) = A2D( 0 , _ );`
| Assign upper part of A2D     | `B2D = A2D(1:2,1:2)`                              | `B2D( _ , _ ) = A2D({0, 2}, {0, 2});`
| Allocatable  declaration     | `real(kind=8), allocatable :: a(:,:)` | `multi::array<double, 2> a;`
| Allocation                   | `allocate(a(10,5))` | `a.reextent({10, 5})` or `a = multi::array<double, 2>({10, 5})`
| Deallocation                 | `deallocate(a)`     | `a.clear()` or `a = {}`
|===

Note that these correspondences are notationally logical;
internal representation (memory ordering) can still be different, affecting operations that interpret 2D arrays as contiguous elements in memory.

Range notation such as `1:2` is replaced by `{0, 2}`, which considers both the difference in the start index and the half-open interval notation in the C++ conventions.
Stride notation such as `1:10:2` (i.e., from first to tenth included, every two elements) is replaced by `{0, 10, 2}`.
Complete range interval (single `:` notation) is replaced by `multi::_`, (or by `_` after the declaration `using multi::_;`).
These rules extend to higher dimensionality.

Multi provides algebraic operators that are expanded elementwise.
For example, a Fortran statement like `C = A + B` or `C = C + A` is translated as this:

[source,cpp]
----
using multi::elementwise::operator+;

multi::array C = A + B;
C = C + A;  // assigning to itself is ok for elementwise operations
----

For one-dimensional arrays, this is equivalent to :

[source,cpp]
----
std::transform(A.begin(), A.end(), B.begin(), A.begin(), std::plus{});  // valid for 1D arrays only
----

Or, in the general dimensionality the equivalent code is:

[source,cpp]
----
auto&&      Aelems = A.elements();
auto const& Belems = B.elements();
std::transform(Aelems.begin(), Aelems.end(), Belems.begin(), Aelems.begin(), std::plus<>{});  // valid for arbitrary dimension
----

or

[source,cpp]
----
std::ranges::transform(A.elements(), B.elements(), A.elements().begin(), std::plus<>{});  // alternative using C++20 ranges
----

A Fortran statement like `C = 2.0*C` is rewritten as

[source,cpp]
----
using multi::elementwise::operator*;

C = 2.0*C;  // self-assignment is ok because this is an elementwise operation
----
(equivalent to `std::ranges::transform(C.elements(), C.elements().begin(), [](auto const& e) { return 2.0*e; });`.)

Simple loops can be mapped as well, taking into account indexing differences (pass:[C++] version on the right):

[source,fortran]
-----
do i = 1, 5         ! for(int i = 0; i != 5; ++i) {
  do j = 1, 5       !   for(int j = 0; j != 5; ++j) {
    D2D(i, j) = 0   !     D2D(i, j) = 0;
  end do            !   }
end do              ! }
-----

link:https://godbolt.org/z/77onne46W[(open with Compiler Explorer)]

However, algorithms like `transform`, `reduce`, `transform_reduce` and `for_each` offer a higher degree of control over operations, including memory allocations if needed, and even enable parallelization, providing a higher level of flexibility.
In this case, `std::fill(D2D.elements().begin(), D2D.elements().end(), 0);` will also work.

[#appendix_numpy]
== Multi for NumPy Programmers

NumPy and Multi share the conventions that matter most for translation: 0-based indexing, half-open ranges (`[first, last)`), and row-major (C-order) storage by default, so most indexing and slicing maps almost directly.

There are two important differences to keep in mind.
First, *assignment semantics*: in NumPy, `B = A` makes `B` another name for the same array (and a slice `A[i:j]` is a view), so an independent array requires an explicit `A.copy()`; in Multi, `auto B = A;` is a deep copy (value semantics), while a reference into existing data is requested explicitly with `auto&& B = A(...);`.
Second, *scope*: unlike NumPy, Multi is not a numerical library, so element-wise arithmetic, broadcasting, reshaping, and concatenation are not first-class operations -- they are expressed with standard algorithms over `.elements()`, or are limited.

|===
|                              | NumPy                              | C++ Multi

| Import / include             | `+import numpy as np+`             | `+#include <boost/multi/array.hpp>+`
| Construction 1D              | `+A = np.array([1, 2, 3])+`        | `+multi::array<int, 1> A = {1, 2, 3};+`
| Construction 2D              | `+A = np.array([[1, 2], [3, 4]])+` | `+multi::array<int, 2> A = {{1, 2}, {3, 4}};+`
| Zeros (given shape)          | `+np.zeros((3, 4))+`               | `+multi::array<double, 2>({3, 4}, 0.0)+`
| Uninitialized (given shape)  | `+np.empty((3, 4))+`               | `+multi::array<double, 2>({3, 4})+`
| Shape                        | `+A.shape+`                        | `+A.sizes()+`
| Number of dimensions         | `+A.ndim+`                         | `+A.num_dimensions()+` (or `+decltype(A)::rank{}+`)
| Total number of elements     | `+A.size+`                         | `+A.num_elements()+`
| Length of first axis         | `+len(A)+`                         | `+A.size()+`
| Element access               | `+A[i, j]+`                        | `+A[i][j]+` or `+A(i, j)+` (or `+A[i, j]+` in C++23)
| Row `+i+`                    | `+A[i]+` or `+A[i, :]+`            | `+A[i]+` or `+A(i, _)+`
| Column `+j+`                 | `+A[:, j]+`                        | `+A(_, j)+`
| Slice of rows                | `+A[i0:i1]+`                       | `+A({i0, i1})+` or `+A.sliced(i0, i1)+`
| 2D block                     | `+A[i0:i1, j0:j1]+`                | `+A({i0, i1}, {j0, j1})+`
| Strided slice (step 2)       | `+A[::2]+`                         | `+A.strided(2)+`
| Transpose                    | `+A.T+` or `+np.transpose(A)+`     | `+~A+` or `+A.transposed()+`
| Main diagonal                | `+np.diag(A)+` or `+A.diagonal()+` | `+A.diagonal()+`
| Flatten (view)               | `+A.ravel()+`                      | `+A.elements()+`
| Reshape                      | `+A.reshape(3, 4)+`                | limited (approx: `+multi::array_ref<int, 2>(A.data_elements(), {3, 4})+`)
| Iterate over rows            | `+for row in A[1]:+`               | `+for(auto&& row : A[1])+`
| Deep copy                    | `+B = A.copy()+`                   | `+auto B = A;+` (use `+auto&& B = A+` or `+= A()+` for a shallow reference)
| View / reference             | `+B = A[i0:i1]+`                   | `+auto&& B = A({i0, i1});+`
| Fill with a constant         | `+A[:] = 7+` (or `+A.fill(7)+`)    | `+std::fill(A.elements().begin(), A.elements().end(), 7)+` or equivalent
| Sum of all elements          | `+A.sum()+`                        | `+std::reduce(A.elements().begin(), A.elements().end())+` or equivalent
| Element-wise `+A + B+`       | `+A + B+`                          | no (use `+multi::elementwise+` operations)
| Broadcasting                 | `+A + b+`                          | no (use `+multi::elementwise+` operations)
| Concatenation                | `+np.concatenate([A, B])+`         | no (approx: use `+std::ranges::concat+`)
|===
